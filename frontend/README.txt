Кадр - frontend

Вебінтерфейс студії відео Кадр. React 19, TypeScript, Vite, Lucide. Вихідний код розділений на компоненти, типи, стилі та ресурси.

Запуск

Потрібні Node.js 22.12 або новіший та npm.

npm ci
npm run dev

Адреса застосунку з’явиться в терміналі. Vite за замовчуванням використовує http://127.0.0.1:5173. Відкрити саме цю адресу в браузері та залишити термінал запущеним. Якщо порт зайнятий, використати адресу з іншим портом, яку показує Vite.

index.html не запускається подвійним кліком. Він підключає src/main.tsx, який Vite перетворює з TypeScript/TSX на JavaScript для браузера. Відкриття через file:// обходить цей процес і може показати порожню сторінку.

npm ci встановлює залежності після розпакування проєкту або оновлення package-lock.json. Для наступних запусків достатньо npm run dev. Папка node_modules створюється автоматично та не потрібна в архіві для передачі.

npm run build
npm run preview

Команда build перевіряє TypeScript і створює статичну збірку в dist. preview запускає перегляд цієї збірки. Файл index.html є точкою входу Vite; для розробки застосунок запускається через npm.

Структура

src/main.tsx - Запуск React і підключення стилів
src/App.tsx - Навігація, стан чернетки, проєкти, імпорт, експорт і завантаження матеріалів
src/Studio.tsx - Чотири кроки редактора та їхня валідація
src/Pages.tsx - Медіатека й налаштування студії
src/AccountPages.tsx - Вхід, реєстрація, відновлення пароля та налаштування акаунта
src/useSession.ts - Відновлення сеансу та оновлення балансу між вкладками
src/api.ts - HTTP-клієнт для акаунта, ціни та генерації
src/GenerationCheckout.tsx - Вартість кліпу, перевірка доступного балансу та підтвердження генерації
src/types.ts - Типи Draft, Project, MediaItem, Settings та значення форматів
src/storage.ts - localStorage, завантаження файлів та формування SRT
src/data.ts - Початкові матеріали, приклади проєктів і локальні шаблони сценарію
src/ui-kit/index.tsx - Спільні компоненти, картки, діалоги та попередній перегляд
src/ui-kit/styles.css - Основні й адаптивні стилі
src/ui-kit/tokens.css - Кольори, відступи та інші токени
src/ui-kit/fonts.css - Підключення локальних шрифтів
public/assets - Фотографії та ліцензія шрифту
vite.config.ts - Конфігурація Vite та проксі для API під час розробки

Дані студії

Чернетки й параметри редактора зберігаються в localStorage цього браузера окремо для кожного акаунта. Згенеровані відео й дані їхніх проєктів зберігає Django. Після входу вони доступні власнику також в іншому браузері. Якщо гість увійде з фінального кроку, поточна чернетка разом із вибраними файлами перейде в його сеанс. Власні вихідні медіафайли доступні до перезавантаження сторінки. Сценарій за шаблоном, зразок голосу, імпорт та експорт JSON/SRT працюють локально.

Підключення Django

Клієнт використовує відносні URL з префіксом /api. Під час розробки Vite передає ці запити на API_PROXY_TARGET (типово http://127.0.0.1:8000). Адресу можна змінити в .env.local. Для збірки dist вебсервер має віддавати фронтенд і проксіювати /api/ під тим самим доменом зі збереженням Host.

Запуск Django з кореня проєкту в PowerShell:

py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000

На Windows збережи токен один раз командою powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\set-replicate-token.ps1 з кореня проєкту. Встав токен у приховане поле й натисни Enter. Django та воркер читають зашифрований файл із %LOCALAPPDATA%\Kadr. Файл доступний для розшифрування під тим самим користувачем Windows. На сервері задай REPLICATE_API_TOKEN через секрети середовища. Змінна середовища має пріоритет над локальним файлом.

У третьому терміналі з кореня проєкту запусти .\.venv\Scripts\python.exe manage.py run_video_worker. Воркер використовує P-Video Draft 720p і FFmpeg із пакета imageio-ffmpeg. Можна задати власний шлях через IMAGEIO_FFMPEG_EXE.

Replicate списує вартість зі спільного рахунку. Тариф сайту задається GENERATION_PRICE_MILLS_PER_SECOND у тисячних долара за секунду (типово 5, тобто $0.005). Повну вартість округлюємо вгору до цента один раз за весь ролик. Django резервує її до першого виклику Replicate, фіксує списання після збереження MP4 та повертає резерв при помилці.

Відеофайли зберігаються в media/generated і доступні через /api/videos/<id>/file/ після перевірки сеансу та власника. Папка зі згенерованими файлами має залишатися приватною для Django.

Посилання для відновлення пароля локально виводиться в терміналі Django. Базова адреса посилання задається FRONTEND_URL (типово http://127.0.0.1:5173). Для доставки листів через SMTP задай EMAIL_HOST, EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD і DEFAULT_FROM_EMAIL.

Сеанс і гроші

Django встановлює HttpOnly cookie сеансу та доступний JavaScript cookie csrftoken. На HTTPS увімкнути Secure для обох cookie. Кожен POST або PATCH надсилає X-CSRFToken. Початковий GET /api/account/ має встановлювати csrftoken також для гостя. Якщо cookie відсутній, клієнт викликає GET /api/auth/csrf/ (204 із Set-Cookie). Перевірка CSRF потрібна також на вході та реєстрації.

Усі суми в API — цілі невід’ємні центи USD. Наприклад, 1250 відображається як $12.50. Об’єкт account має поля id (стабільний рядок), name, email та balance_cents. Сховище балансу, джерело тарифів і грошові операції належать бекенду. Для чутливих відповідей встановити Cache-Control: no-store.

Акаунт та авторизація

GET /api/account/ → 200 {"account":null} для гостя або {"account":{"id":"42","name":"Олена","email":"olena@example.com","balance_cents":1250}} для користувача. Також підтримується 401 при завершенні сеансу.
POST /api/auth/register/ з JSON {name,email,password} → 201 {account} та cookie нового сеансу.
POST /api/auth/login/ з JSON {email,password} → 200 {account} та cookie сеансу.
POST /api/auth/logout/ → 204, сеанс закрито.
PATCH /api/account/ з JSON {name,email} → 200 {account}. При зміні пошти додається current_password. Бекенд перевіряє пароль та унікальність адреси.
POST /api/account/password/ з JSON {current_password,new_password} → 204. Після зміни пароля поточний сеанс зберігається.
POST /api/auth/password-reset/ з JSON {email} → 204 незалежно від наявності адреси. Бекенд надсилає лист із посиланням на /#reset-password?uid=...&token=... . Значення параметрів мають бути URL-кодовані.
POST /api/auth/password-reset/confirm/ з JSON {uid,token,new_password} → 204. Бекенд перевіряє строк дії та одноразовість посилання.
Валідація паролів на формі реєстрації, зміни й відновлення передбачає мінімум 8 символів. Сервер застосовує власні перевірки. Для відмов API повертає JSON {"detail":"Повідомлення українською"} та відповідний HTTP-статус. Для помилок полів і неправильного поточного пароля використовувати 400. Статус 401 на захищених маршрутах означає завершений сеанс.

Тестове поповнення та витрати

У вкладці «Аккаунт» кнопка «Поповнити баланс» відкриває поле введення суми в USD. POST /api/account/top-up-requests/ створює заявку зі статусом pending і повертає 201. Повтор того самого request_id із тією самою сумою повертає створену заявку. GET /api/account/top-up-requests/ повертає заявки лише поточного користувача.

Для першого входу в адмінку створи суперкористувача командою .\.venv\Scripts\python.exe manage.py createsuperuser. Відкрий http://127.0.0.1:8000/admin/ і вибери «Акаунти» або «Заявки на поповнення». Після ручного поповнення спільного рахунку Replicate познач відповідну заявку та вибери дію «Підтвердити після поповнення Replicate та зарахувати баланс». Django зараховує суму лише один раз. Відхилена заявка не змінює баланс. Користувач може перечитати статуси й баланс кнопкою «Оновити заявки й баланс».

Історія витрат

GET /api/account/expenses/ повертає списання за генерації для користувача поточного сеансу, від найновішого до найстарішого. Кожен запис відповідає остаточному списанню. Тестові поповнення та резервування належать до окремих видів операцій.

Приклад сторінки історії
{"results":[{"id":"expense-42","created_at":"2026-11-21T12:30:00Z","project_title":"Ранок у Карпатах","amount_cents":75}],"next_cursor":"page2"}

id — стабільний рядковий ідентифікатор списання. created_at — дата й час у форматі ISO 8601 із часовим поясом. Клієнт відображає час за Києвом. project_title — назва проєкту на момент генерації або null, тоді інтерфейс показує «Генерація відео». amount_cents — додатна сума списання у центах USD.

Кнопка «Показати ще» запитує GET /api/account/expenses/?cursor=... зі значенням next_cursor попередньої відповіді. На останній сторінці next_cursor дорівнює null. Для порожньої історії повертати 200 {"results":[],"next_cursor":null}. Прострочений сеанс повертає 401.

У підсумку історії можна показати total_spent_cents з об’єкта account. Це сума остаточних списань за весь час, включно зі сторінками, які користувач ще не відкрив. Значення 0 відображається як $0.00. Коли поле пропущено або дорівнює null, підсумок прихований.

Ціна та фінальна генерація

1. На фінальному кроці авторизований клієнт викликає POST /api/generation/quote/ з JSON {duration,aspect_ratio}. Django приймає від 1 до 60 цілих секунд і повертає quote_id, price_cents, balance_cents, duration та account_id. Запит ціни не списує грошей.
2. Клієнт показує ціну, баланс і фактичну тривалість. Якщо коштів бракує, видно суму нестачі й кнопку оновлення. Достатній баланс дозволяє користувачу підтвердити суму кнопкою генерації.
3. POST /api/generate-video/ приймає погоджений quote_id і дані проєкту. Стартове фото JPG, PNG чи WebP до 10 МБ або image_url можна додати за бажанням. Django резервує баланс і повертає 202 з ID завдання. Повтор із тим самим quote_id повертає стан завдання або готовий результат.
4. React опитує GET /api/generation/jobs/<id>/, де власник бачить статус і кількість готових частин. Воркер генерує частини до 10 секунд, передає останній кадр попередньої частини як старт наступної та зводить фінальний MP4 із відео 24 FPS і аудіо 48 кГц.
5. Недостатній баланс повертає 402, а прострочена або змінена пропозиція — 409. Успішний MP4 доступний у проєктах власника, навіть якщо браузер було закрито.
